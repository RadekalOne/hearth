# Hearth relay live adapters design

Rad requests real intake, allowance checks and unattended launcher, keeping the installed relay disabled until checks pass, paid runs explicitly gated and production unchanged. This extends the approved relay interfaces; it does not activate them or reopen the frozen credential-inventory track. No API-key route, account/billing setting change, automatic reset, merge or production deployment.

Use the existing fixed Agent Tasks room/thread and sender identities. Implement direct authenticated bounded Matrix HTTPS reads using only the existing host-side Matrix credential source, never copying its broader environment into a child. Parse a versioned JSON relay-work envelope only from an original Rad [APPROVED] event, bound to exact base/scope/review generation. Fetch source review text separately as untrusted task data. Durable intake staging and cursor commits prevent lost work across bounded pagination and crashes. Missing cursor/gaps refuse; no whole-room replay or read marker. Tests may use a localhost HTTP fixture with an explicit fixture constructor; production uses TLS, fixed origin, no proxies/redirects and bounded responses. Real validation is read-only; no synthetic room messages.

Use a separately pinned existing Windows Codex 0.164.0 for the new laptop adapter; do not alter the reviewed Linux 0.159.1 trial client or install/update any app. The model remains exactly gpt-6.1-sol. A bounded stdio process uses a fresh private CODEX_HOME, fixed no-shell/no-apps/no-plugins profile and existing selected ChatGPT access token supplied in memory through the documented external-token protocol. No token refresh/login UI, new credential, copy of auth.json, global config/cache mutation or broad Hearth token in the process. Read-only metadata includes account/read with refresh=false, account/rateLimits/read and model/list. Hash/pin binary and schema provenance; malformed/unknown/expired data refuses. No account/rate-reset consume or purchase API.

Capacity and financial authority are separate. Native quota/credit data can establish current capacity, not a hard $0 boundary. Every model turn remains blocked unless the exact scoped Rad paid-run approval AND a separately verified spend/route boundary are present. Missing billing proof remains an explicit refusal reason, not a caller boolean or a fictitious included_only result. The current instruction approves build/verification, not a model turn. No real inference during this increment.

The one-attempt launcher is a deterministic host controller. It uses a pinned, contained native process with bounded protocol/output/time, original epoch/dispatch fencing, durable send-stage accounting and an external process-tree stop. It runs a read-only, tool-free proposal turn; the host alone can validate a bounded text-change proposal against the approved paths/base hashes into an isolated snapshot. No repository or room text can choose an executable, provider, credential, command, checkout root or broaden tools. Untrusted tests, when needed, run only in the established credential-free network-none trial container, never the credential-bearing host. A real-model/filesystem-tool acceptance is not inferred from a fake provider.

Wire the existing HostPorts to the concrete adapters through a private hash-bound configuration. Keep no-config fail-closed, no enable command and scheduler disabled. A manual diagnose operation may fetch read-only live Matrix/native metadata while paused without claiming or posting. Real launch verification remains gated and reports unavailable facts honestly. Native process/profile and test sandbox must have independent cleanup proof before a slot is released; uncertainty remains held/pending and never retries.

Validation: TDD fake Matrix/native process tests for authority, redirects/proxies, pagination/cursors/dedup, transient failures, stale/exhausted/unknown allowance, no paid dispatch, exact model/profile, bounded events, crash/pause/cleanup, proposal scope and secret absence. Read-only real Matrix whoami/event reads and native account/model metadata; no turn/start. Full canonical-source network-none suite and one final fresh-context whole-increment review, with one RED/GREEN Important fix pass. Exact diff/evidence to Claude in existing thread. Financial/native-model/activation proof stays separately gated.

Preserve the existing hourly 07:00-23:00 ET schedule, interactive-user requirement, no wake/catch-up, independent Pause button, audit and inactive900s/full-run policy. The pinned native schema cannot establish a server-enforced included-only monetary boundary. Therefore this increment does not deliver an operative unattended model launcher: real turns remain blocked, approved generations stay pending/unclaimed, and the positive proposal protocol is explicitly a credential-free fixture. No fake paid permit, caller boolean or human budget can turn quota into financial enforcement. Activation is intake/capacity only, not an autonomous coding loop. Completing actual model execution requires a separately reviewed financial authority/route design and scoped Rad APPROVED. This is an explicit outstanding requirement, not a passed gate.
