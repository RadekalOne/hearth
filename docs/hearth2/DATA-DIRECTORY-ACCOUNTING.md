# Conditional file acquisition and source accounting

`DirectorySourceCapture.capture(requirements, manifest, begin=...)` connects the
private two-pass file reader to the existing pinned credential parsers. This is
the next small offline increment underneath Task3 of the data-directory plan.
Default view is absent/refuses. It is not an independently enrolled scanner,
installed helper, full root policy/source map or credential-inventory producer.

Before filesystem acquisition it validates both immutable conditional coverage
requirements and the complete existing 17-kind source manifest. Original
image/container/assembly/policy must agree; source IDs/kinds and declared group
membership must match. Every OAuth group belongs to this root, and supported
store/state paths match its explicit build environment and region. It never
derives namespace/account identity from token content or borrows a partner from
another group. Account identity remains a supplied hypothesis, not a verified
native account binding.

The intentionally narrow conditional map reads only `codex-auth.json`,
`config.yaml`, and `auth/<env>/<region>/mcode-public/{auth.json,auth-state.json}`.
Other file roles, environment, host model reference and MCP consumers have no
mapped path in this increment and stay unscanned. Paths for unsupported roles
are refused before acquisition. This is not the full independently audited
native path-resolution/profile/root universe and must not be promoted to one.

Both passes use the existing descriptor-relative no-follow/type/identity/mount
and stable-listing checks. Bodies and comparison digests stay inside the call;
only after two-pass agreement does the pinned accounting layer consume private
buffers. The smaller acquisition/audit byte and time budgets win, with work
charged across BOTH passes. Budget/changed-root failures return no accounting
result. No source bytes, token values, filesystem paths, caller source/group IDs
or comparison hashes appear in returned summaries. Bodies are not saved to a
file, callback, instance cache or handoff. This is not a guarantee of secure
memory erasure, interpreter isolation or protection from debugging/tracebacks.

Existing empty/malformed files remain present but unsupported by accounting.
Oversize/IO/permission problems are unreadable, not absent. Unsafe filesystem
objects are unsupported in the coverage view and unreadable in the accounting
view; neither interpretation clears uncertainty. Unsafe sibling evidence blocks
dependent absence while independently stable readable material is preserved.
Known syntax counts can survive missing runtime selection or OAuth partners;
incomplete effective interpretation remains unsupported. No credential is
resolved, command executed, native client started or provider contacted.

The result contains separate conditional coverage and source-accounting
summaries, fixed enums, ordinal outcomes and work/read counts. ALL three image
or seven stopped-container physical families ALWAYS remain unresolved. There is
no scan/complete/observe/start authority or assembly-collector wiring.

Remaining gates: independent root/image/CID/host and source-map enrollment,
configured root discovery bracketing, complete native-consumer semantics,
credential custody, pinned interpreter/parser closure, fresh process per root,
external hard timeout and verified reap. In-process elapsed checks cannot kill
blocked OS calls; two live passes do not establish an atomic frozen view.
The previously deferred canonical `..` root-spelling issue remains a
pre-production gate. No production use or physical acceptance is claimed.

Tests use private synthetic files with fake values only. They cover actual Pi
and OAuth parsing, config material despite missing runtime context, namespace
separation, unsafe/empty/malformed/oversize/permission input, cross-pass changes,
original context and scope mismatches, lower audit budgets, container unresolved
families, sequential-call isolation and public-output redaction. Final review
and immutable full-suite verification are recorded at closeout.
